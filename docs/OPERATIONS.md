# 日常操作与故障排查

以下命令在部署 Demo 的服务器普通用户终端运行，目录固定为 `~/btc-v53-demo`。只对 `btc-v53-demo.service` 操作。

## 查看状态

```bash
cd "$HOME/btc-v53-demo"
python3 status_view.py
python3 launch.py status --local
python3 launch.py status --local --json
systemctl --user status btc-v53-demo.service --no-pager
journalctl --user -u btc-v53-demo.service -n 80 --no-pager
```

普通状态会通过配置代理查询 OKX 公开时间接口；本地状态跳过网络检查。代理端口接受连接不等于能到 OKX；公开接口成功也不等于私有账户、下单或止损已验收。`active` 只表示进程还在运行，应同时看阶段、最近检查时间、未决请求、逐笔成交核对和持仓记录。

| 阶段 | 含义与处理 |
| --- | --- |
| 尚无账本 | 尚未成功 `arm-demo`；仅上传代码不会允许交易 |
| `armed` | Demo 已启用，循环尚未开始 |
| `warming` | 正在补齐历史行情；首次启动常见，不补下历史订单 |
| `running` | 本轮检查正常，按条件等待或管理模拟仓位；不保证马上开仓 |
| `paused` | 禁止新开仓和补仓，继续管理已有仓位 |
| `reconciling` | 原订单或撤单结果仍在核对；等待明确结果，不重复下单 |
| `protection_pending` | 止损确认未完成；禁止增加风险，需核对 Demo 界面 |
| `closing` | 已处理退出请求；必须继续确认成交、空仓和未决订单 |
| `attention` | 网络、账户或数据检查失败；读取脱敏消息并核对原因 |
| `halted` | 风控停止；`resume` 不能解除 |
| `stopped` | 进程已退出；不代表平仓 |

记录超过 90 秒、服务停止或阶段尚未就绪时，页面会提醒内容可能是旧记录。预热阶段有近期检查也不会显示成已经正常交易。

## 暂停、平仓与停止的区别

| 操作 | 命令 | 效果 |
| --- | --- | --- |
| 暂停新增风险 | `python3 launch.py pause` | 由下一轮处理，停止新开仓和补仓，继续核对和管理已有仓位 |
| 恢复条件检查 | `python3 launch.py resume` | 原因已排除后才使用；等待下一根新小时信号，不能解除风控停止 |
| 请求平仓 | `python3 launch.py flatten` | 暂停新增风险并请求退出；返回成功只表示请求已写入队列 |
| 停止进程 | `systemctl --user stop btc-v53-demo.service` | 停止程序；不会替你平仓 |

控制命令需要服务运行后才能处理；服务已经停止时，请求会等待。需要退出并停机时：

```bash
python3 launch.py flatten
python3 status_view.py
```

保持服务运行，直到最近对账显示空仓、无未决经济订单，并在 **OKX 模拟交易界面**核对持仓和普通/算法挂单，随后再停服务：

```bash
systemctl --user stop btc-v53-demo.service
```

如果程序失去网络或无法处理退出，在 OKX Demo 界面人工核对，不要把停止服务当作已退出。程序停止后，曾确认的交易所止损仍由交易所处理，但本地不会持续管理或确认它；止损登记本身不保证成交。

启动已有安装用 `systemctl --user start btc-v53-demo.service`，不需要重新 `arm-demo`。如果服务仍然启用，之后重启系统会再次尝试启动；如需长期停用，可执行 `systemctl --user disable btc-v53-demo.service`。

## 常见问题

**代理端口不通或公开检查失败：** 按 [代理说明](PROXY.md) 检查本机 `127.0.0.1:17890`、同用户 Mihomo 状态及线路。没有代理时程序不会静默改为直连。若代理由实盘共用，不要为 Demo 排障停止它或随意切换节点。

**Demo 账户检查失败：** 在 OKX 模拟交易里确认密钥环境、读取/交易权限、账户模式、逐仓 15 倍、可用 USDT 和空仓无挂单条件。不要把实盘 Key 填进来测试。费用组字段缺失或费用超预算时程序拒绝继续，不会用旧手续费字段或猜测值兜底。

**一直 `warming`：** 查看“行情最后一分钟开始”和最近检查时间是否推进。历史缺口、空页或已缓存行情修订会阻止信号计算，读日志中的脱敏提示；不要手工制造 K 线，也不要删除账本重启。

**账本身份不同 / 冻结源校验失败：** 本地代码、配置、账户或密钥发生过变化。停止升级操作，保留原程序和账本，核查差异。不要改哈希清单、清空 `var/demo` 或重新 arm 以绕过绑定。

**服务锁提示已有进程：** 查本机是否还在运行相同 Demo 账户的另一副本。历史公共锁在 `~/.local/state/btc-v53-live/locks/`，按 `mode + uid` 区分账户；这是跨旧目录的重复运行保护，不是实盘账本路径。该锁不能覆盖另一台主机或另一个 Linux 用户，仍应避免复用同一 Demo 账户。

**网络恢复但仍暂停：** 部分结构性错误会持久化暂停。先核对交易所持仓、订单及本地账本；确认原因排除后才执行 `resume`。网络重连不会清除所有暂停状态。

## 备份与升级

`credentials.env`、`var/demo/` 和交易日志只保存在你控制的位置，不上传 GitHub。需要一致的文件级账本备份，应先处理仓位与未决请求并停止服务，再将整个 `var/demo/` 连同相关 SQLite 文件一起保存；不要在写入中只复制一个数据库文件。

发布仓库只存干净源码、配置模板和离线测试。本版本是新安装/归档包；没有账本迁移工具，不支持对正在运行的目录直接覆盖或 `git pull`。升级前应单独审查代码绑定、旧账户仓位、订单和迁移方案。
